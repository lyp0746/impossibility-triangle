第24章　三角的十个反例

十个反例里有一个是作者自己遇到的：一家小作坊，三样都做到了。他写道：“我原来的说法太强了，它只在复杂度足够高时成立。”愿意把框架缩小，通常是被现实说服了。

一个框架最该被检验的，是“反例”。本章列十个“看起来像反例”的系统，并逐个说明：它到底推翻了三角，还是只是“换了一种让出方式”。

24.1　小手工作坊

现象。三样都不高，却长期稳定。读法。它靠“低复杂度”与“外部补贴”维持；三角的预算 K 很小，K 小到“三样都不满”也能活。不是反例，是“低预算均衡”。

24.2　开源社区

现象。完备性不高、可组合性很高、传递性中等。读法。它选了 A+T，让出 C；文档与边界案例的缺失，就是 C 的账单。

24.3　极权体制

现象。决策快、执行强、信息失真。读法。它选了 A+T，让出 C；“信息失真”就是 C 的账单。

24.4　学术共同体

现象。局部很完备、可组合、但跨学科传递难。读法。C+A，让出 T；“学科壁垒”就是 T 的账单。

24.5　大语言模型

现象。参数记忆强、组合强、但跨尺度一致弱。读法。C+A，让出 T；“幻觉与不一致”就是 T 的账单。

24.6　传统医学

现象。局部经验完备、组合灵活、但跨体系传递难。读法。C+A，让出 T；“难以标准化”就是 T 的账单。

24.7　中央银行

现象。工具可组合、长期可追踪、但单情形预测难。读法。A+T，让出 C；“预测失灵”就是 C 的账单。

24.8　天气预报

现象。短期精确、长期发散。读法。它其实在 A+T 与 C 之间切换；τ 越大，C 越贵。

24.9　家族企业

现象。内部信任强、外部传递弱。读法。C+A，让出 T；“跨代传承难”就是 T 的账单。

24.10　一个“真反例”的候选

候选。有没有系统“三样都满”？目前没有找到。但这不等于“永远找不到”。本书把它登记为开放问题，而不是“已证不可能”。

24.11　适用范围与反例库：三角怎样才算被反驳

对三角最有力的批评不是“举一个反例”，而是：它能不能把任何反例都吸收成“你其实让出了某一项”？ 如果能，它就不是诊断，而是同义反复。这一节给出可操作的反驳条件，以及一份反例库。

系统充分保住的让出的证据类型
急诊分诊C + AT（跨科室结论难无损传递）流程记录（B）
大科学协作（如 LIGO）A + TC（单个子系统的完备描述被牺牲）项目文档（B）
工匠式单件生产C + TA（不可组合、不可放大）田野观察（B–C）
开源内核开发A + TC（全局一致性靠审查而非完备描述）提交记录（B）
“三样都要”的声称—至少一项是量度松弛需逐项复核（C）

三条可反驳条件（缺一不可）。

  1. 量度必须事前指定。 说“它三样都有”之前，先写清 C、A、T 各自怎么测。事后换量度来救框架，不算反驳，也不算证据。
  2. 必须给出同一系统、同一时段的对照。 不能拿 A 系统的 C 与 B 系统的 T 拼成“三样都有”。
  3. 必须允许“框架失效”这一结果。 若出现一个系统，在事前量度下长期同时满足三项，并且不能归因于资源无限或复杂度极低，那么三角在这个范围内失效——这一条写在这里，就是它被证伪的入口。

为什么把这张表放在正文。因为反例不是附录里的礼貌，而是框架的承重墙：一个不能被反例推翻的三角，不值得被引用；一个能被反例精确限定的三角，才有资格被使用。

人的尺度

十个反例里，有一个是作者自己遇到的：一家小作坊，三样都做到了。他写道：“我原来的说法太强了，它只在复杂度足够高时成立。”一个人愿意把自己的框架缩小，通常是因为他在现实里被一个小作坊说服了。

本章小结
  • 十个反例里有九个是"复杂度不足时三角不成立"。
  • 这说明三角是一个有范围的经验判断，不是普适定律。
  • 反例进正文，是为了让读者知道它在哪失效。

一句话带走：十个反例提醒：三角是有范围的判断，不是普适定律。
